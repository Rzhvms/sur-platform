# API рисков и бизнес-журнала

Маршруты используют существующие префиксы `/api/v1/public` и `/api/v1/provider`. Swagger группирует операции по контроллерам. Клиент определяется по зарегистрированному HTTPS-хосту.

| Метод и путь после `/api/v1` | Контракт |
| --- | --- |
| `GET /public/risk-references/{kind}` | Активные группы опасностей, опасности с активной группой или категории |
| `GET /public/risk-references/processes` | Активные процессы для создания риска с учётом дирекции пользователя |
| `GET /public/risk-references/assets` | Активные объекты с допустимой стоимостью часа простоя |
| `GET, POST /provider/risk-references/{kind}` | Список всех записей вида и создание активной записи |
| `PUT /provider/risk-references/{kind}/{id}` | Редактирование, активация или деактивация с проверкой `version` |
| `GET /public/risks` | Страница реестра |
| `GET /public/risks/board` | Шесть колонок со счётчиками и отдельной страницей в каждой |
| `GET /public/risks/{id}` | Паспорт, связи, оценки и признак доступности редактирования |
| `POST /public/risks` | Создание черновика и основной связи с процессом |
| `PUT /public/risks/{id}` | Сохранение паспорта с проверкой `version` и истории оценок |
| `POST /public/risks/{id}/close` | Закрытие с обязательными `version` и `reason` |
| `POST /public/risks/{id}/reopen` | Возврат на переоценку с `version`, для закрытого риска требуется `confirmed: true` |
| `GET, POST /public/risks/{riskId}/comments` | Список неудалённых комментариев и создание комментария |
| `PUT, DELETE /public/risks/{riskId}/comments/{id}` | Редактирование или логическое удаление по версии. Для DELETE версия передаётся в query |
| `GET /provider/business-history` | Административная страница журнала по датам `from` и `to` |
| `POST /provider/business-history/exports` | Создание снимка журнала по датам `from` и `to`, ответ содержит идентификатор снимка |

Виды справочников в пути — `HazardGroups`, `Hazards`, `Categories`. Для опасности обязателен `groupId`. Реестр и доска принимают `search`, `directorateId`, `processId`, `ownerId` (ID сотрудника), `assetId`, `categoryId`, `status`, `sort=recent|name`, `offset` и `limit`. Счётчик колонки равен числу карточек в `items` на возвращаемой странице. Статусы идут в порядке `DRAFT`, `ACTIVE`, `IN_PROGRESS`, `AWAITING_REVIEW`, `ACCEPTED`, `CLOSED`. Если текущей оценки нет, `currentAssessment` равен `null`. Карточка риска, ожидающего переоценки, может вернуть последнюю завершённую оценку в `previousAssessment`.

При создании передаются `name`, `description`, `hazardId`, `categoryId`, `processId` и необязательный `assetId`. При редактировании передаётся полный паспорт с `version`, а `processId` опускается. Устаревшая версия возвращает `409`. Первая запись оценки блокирует редактирование паспорта. Проверка незавершённых мер при закрытии относится к этапу 5.

Команды изменения получают общую блокировку с Identity и оргструктурой и перепроверяют актуальные права в той же транзакции. Изменения данных, исторические версии отчётных источников и поручения журнала фиксируются вместе. При смене владельца процесса в операцию входят действующие связи риска и системные комментарии. Воркер работает в контексте каждой подготовленной клиентской базы и повторяет перенос по `eventId`. Административная выборка и снимок объединяют журнал и ожидающие поручения с устранением дублей. Даты `YYYY-MM-DD` включительны в UTC. Формирование JSON-файла относится к этапу 8.

## Оценка и решения

| Метод и путь после `/api/v1` | Контракт |
| --- | --- |
| `GET /public/risk-assessment-settings/matrix` | Встроенный метод, стабильные ID уровней 0–5, матрица из 25 положительных ячеек |
| `GET /public/risk-assessment-settings/impact-scale[/{id}]` | Текущая или историческая денежная шкала |
| `GET, PUT /provider/risk-assessment-settings/impact-scale` | Просмотр и публикация шкалы. Для первой публикации передаются `minimums`, для последующих также `version` |
| `GET, PUT /provider/risk-assessment-settings/acceptance` | Пороги маршрутов, версия и флаг `applyToExisting` |
| `POST /public/risks/{id}/assessments/preview` | Предварительный расчёт по `likelihoodLevelId` и сумме либо компонентам простоя |
| `POST /public/risks/{id}/assessments` | Бизнес-оценка. Передаются `version`, `scaleVersionId`, `assetVersion` для связанного объекта и `inputs` |
| `GET /public/risks/{id}/assessments` | История оценок с `offset` и `limit` |
| `POST /public/risks/{id}/accept` | Принятие на сохранённом уровне с актуальным правом и назначением или правом `admin` |
| `POST /public/risks/{id}/treat` | Выбор обработки с версией риска |
| `GET /public/risks/{id}/split/processes` | Допустимые процессы для разделения риска |
| `POST /public/risks/{id}/split` | Полный список `processIds`, один `primaryProcessId` из списка и версия риска |

До публикации первой денежной шкалы расчёт возвращает `409 RISK_SCALE_REQUIRED`. Оценка, активация риска и поручение журнала фиксируются вместе. Изменение шкалы или ставки объекта создаёт техническую версию оценки для применимых рисков с сохранением режима. Изменение порогов принятия с `applyToExisting` обновляет маршруты без пересчёта оценки. Принятые и закрытые риски сохраняют исходные значения. Передача требует команды пересмотра этапа 6. Проверки зависимостей по мерам подключаются на этапе 5.
