# Меры, согласования и исполнители

| Метод и путь после `/api/v1` | Назначение |
| --- | --- |
| `GET, POST /public/risks/{riskId}/treatments` | Меры риска и создание черновика |
| `POST /public/risks/{riskId}/treatments/start` | Атомарный запуск ожидающих мер |
| `GET, PUT /public/treatments/{id}` | Карточка и редактирование черновика |
| `GET, POST /public/treatments/{id}/approvals` | История запросов и отправка на согласование |
| `GET /public/treatment-approvals` | Очередь и счётчик по актуальным правам и организационным назначениям |
| `POST /public/treatment-approvals/{id}/approve`, `/reject`, `/revoke` | Решение по версии запроса. Для отклонения и отзыва обязательна `reason` |
| `GET /public/treatments/{id}/executors` | Допустимые исполнители дирекции процесса |
| `POST /public/treatments/{id}/dispatch` | Назначение `assigneeId` и переход к ожиданию в одной операции |
| `PUT /public/treatments/{id}/assignment` | Замена исполнителя, назначение или снятие в холде |
| `POST /public/treatments/{id}/hold`, `/resume`, `/complete`, `/cancel` | Ручные переходы. При завершении `costActual` необязательна |
| `GET, POST /public/treatments/{id}/comments` | Просмотр комментариев и добавление |
| `PUT, DELETE /public/treatments/{id}/comments/{commentId}` | Изменение или логическое удаление. Для DELETE версия передаётся в query |
| `GET, PUT /provider/treatment-approval-settings` | Пороги согласования с начальной настройкой 0, 50 000 и 100 000 рублей |

Изменяющие операции существующих записей принимают `version`. Черновик принимает `title`, `description`, `dueDate` в формате `YYYY-MM-DD`, `costPlanned`, необязательную `costActual` и при нескольких связях `riskProcessId`. Для выбора связи используйте `data.processes[].riskProcessId` из `GET /api/v1/public/risks/{id}`. Списки поддерживают `offset` и `limit`.

Миграция `202611140500` хранит стабильную пару риск–процесс под составным внешним ключом к версии связи. Частичный уникальный индекс защищает слот через текущие и исторические связи. Отдельные уникальные индексы защищают открытый запрос и текущее назначение.

Изменение меры, связанного запроса, назначения и запись поручения журнала выполняются в одной клиентской транзакции. Общая блокировка с Identity и оргструктурой сериализует назначение и деактивацию. Журнал фиксирует смену исполнителя, а история запроса сохраняет исходное решение после отзыва.

Завершение последней активной меры открывает пересмотр в той же транзакции. При наличии черновиков и отсутствии подтверждения сервер возвращает `409 TREATMENT_CONFIRMATION_REQUIRED`. Запись поручений Jira подключается на этапе 7 внутри транзакции запуска.
