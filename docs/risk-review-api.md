# Пересмотр риска

| Метод и путь после `/api/v1` | Операция |
| --- | --- |
| `POST /public/risks/{id}/reopen` | Ручной пересмотр принятого или закрытого риска. Для закрытого передайте `confirmed: true` |
| `GET /public/risks/{id}/transfer/processes` | Новые процессы, доступные для передачи |
| `POST /public/risks/{id}/transfer` | Передача в `processId` с ожидаемой `version` |
| `GET /public/risks/{id}/reviews` | Постраничная история с результатом и снимком источника |
| `POST /public/risks/{id}/assessments` | Новая оценка и завершение открытого пересмотра |
| `POST /public/risks/{id}/close` | Закрытие с причиной и завершение открытого пересмотра без оценки |
| `GET, POST /provider/review-schedules` | Список и настройка расписаний |
| `PUT, DELETE /provider/review-schedules/{id}` | Изменение, в том числе `isActive`, и удаление |
| `GET, POST /provider/review-webhooks` | Список и создание внешних источников |
| `GET, PUT, DELETE /provider/review-webhooks/{id}` | Карточка, изменение области или активности, удаление |
| `POST /provider/review-webhooks/{id}/rotate-token` | Замена секрета с `version` и `confirmed: true` |
| `POST /public/review-webhooks/{id}` | Приём HTTPS-сигнала с отдельным Bearer-секретом, ответ `202` с `reviewRunId` |
| `GET /provider/review-runs` | История первичной обработки, включая пустые календарные запуски |

Карточка риска включает открытый пересмотр и первую страницу истории в `reviews`. Результат содержит `review` и `run` со снимками источника, ответственного и автора настройки. На списках доступны `offset` и `limit`. Версия при удалении настройки передаётся в query.

Расписание использует календарную зону из `Application__TimeZone` с исходным значением `UTC`. Зона сохраняется при создании. Для недели передаются дни ISO от 1 до 7. Для месяца и года число даты ограничено последним днём месяца. Лимит числа срабатываний учитывает пустые запуски. Обработчик регистрирует текущую локальную дату и продолжает ранее сохранённые запуски. Он не формирует задним числом выборки для дней, когда служба была выключена.

Идентификатор настройки вебхука является ключом его адреса. Секрет возвращается при создании и ротации. В таблице настройки хранится SHA-256 случайного секрета, сравниваемый в постоянном времени. Тело до 1 МиБ сохраняется побайтно после проверки секрета. Область и внешний источник берутся из настройки. Ответы истории не включают исходное тело или хеш секрета.

Команды передачи, ручного возврата, завершения последней меры, переоценки и закрытия используют общую клиентскую транзакцию и блокировку. Календарный или внешний запуск сначала сохраняется со снимком целей, затем каждая цель обрабатывается своей транзакцией. Уникальные ключи защищают календарную дату расписания, пару запуск–риск и открытый пересмотр риска. Переоценка и закрытие изменяют конкретный пересмотр, сохраняя итог запуска.
