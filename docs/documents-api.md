# Файлы, отчёты и импорт CSV

Все пути приведены после `/api/v1`. Задания и файлы принадлежат пользователю, который создал операцию, в базе выбранного HTTPS-клиента. ID задания сохраняется при повторе, а при подтверждении файла становится его `fileId`.

| Метод и путь | Назначение |
| --- | --- |
| `POST /public/documents/reports` | Зарегистрировать снимок реестра, опционально сформировать CSV или XLSX |
| `POST /provider/documents/history` | Сформировать административный JSON за включительный диапазон дат UTC |
| `POST /public/documents/imports` | Зарегистрировать ожидаемый исходный CSV |
| `PUT /public/documents/{id}/file` | Загрузить CSV как `application/octet-stream` с `Content-Length` |
| `PUT /public/documents/{id}/mapping` | Зафиксировать сопоставление и запустить импорт |
| `GET /public/documents/{id}` | Состояние, подтверждённый `fileId`, код ошибки, возможность повтора и счётчики импорта |
| `GET /public/documents/{id}/rows?after=0&limit=128` | Порция готового снимка реестра или результатов импорта |
| `GET /public/documents/{id}/file` | Скачать готовое вложение, ответ содержит `X-Content-SHA256` |
| `POST /public/documents/{id}/retry` | Возобновить задание после временного сбоя или заново подтвердить право |

Клиент генерирует UUID `operationId` до отправки запроса создания и использует его при сетевом повторе. Один ключ для тех же пользователя, назначения и параметров возвращает прежнее задание. Повтор с изменёнными параметрами возвращает `409 DOCUMENT_CONFLICT`. При временной ошибке используется маршрут `retry`, а исправленный CSV регистрируется с новым `operationId`.

## Отчёт и административная история

Тело запроса снимка включает `operationId`, опциональные `asOf` (дата и время со смещением), `processId`, `directorateId`, `categoryId`, `status` и `format` (`CSV` или `XLSX`). Без формата создаётся снимок для просмотра страниц. Право `view_report` требуется для просмотра, для файлового отчёта дополнительно требуется `export_report`. Автор отчёта записывается как UUID пользователя. Числовые значения оценки и стоимости в XLSX записываются числовыми ячейками, пользовательский текст — текстовыми. Для CSV потенциальные формулы экранируются маркером текстового значения.

История требует `admin`. Тело содержит `operationId` и `period` с датами `from` и `to` в формате YYYY-MM-DD. Готовый файл содержит массив событий, включая `[]` для пустого периода. Ранее опубликованные маршруты истории и экспортного снимка остаются доступны.

При запросе текущего отчёта фоновый обработчик определяет момент среза в транзакции материализации. Для исторического среза берётся последняя сохранённая версия каждого источника на `asOf`. Миграция `202611140800` фиксирует недостающие текущие версии источников на дату установки. Сведения до первой сохранённой версии отсутствуют в историческом срезе. Это, в частности, касается мер, изменённых до установки этапа 8. Порции читаются из одного неизменяемого снимка.

## Импорт

Права на регистрацию и выдачу источника определяет `import_data`. Запуск и обработка каждой строки дополнительно требуют `create_risk`, включая действующую сессию и правила регистрации в дирекции. Файл — UTF‑8 с необязательным BOM, до 8 МиБ. Перед загрузкой клиент передаёт размер `size` в байтах и `checksum` как 64 hex-символа SHA‑256. После подтверждения загрузки задание переходит в `AWAITING_MAPPING`.

Пример сопоставления с индексами от нуля.

```json
{
  "delimiter": ",",
  "hasHeader": true,
  "columns": {
    "Name": 0,
    "Description": 1,
    "HazardId": 2,
    "CategoryId": 3,
    "ProcessId": 4,
    "AssetId": 5
  }
}
```

Разделитель — запятая или точка с запятой. `AssetId` необязателен. Идентификаторы справочников передаются как UUID. Кавычки и переводы строки внутри кавычек обрабатываются CSV-парсером. Номера начинаются с 1 после заголовка и относятся к записям CSV. Результат строки содержит `riskId` или `code`. `COMPLETED_WITH_ERRORS` сохраняет успехи и ошибки строк. При ошибке кодировки, превышении лимита или недоступности источника ранее подтверждённые строки остаются доступны.

## Хранилище и проверки

Настройки MinIO задаются через `Documents:Minio` в appsettings или переменные среды `Documents__Minio__Endpoint`, `Documents__Minio__Bucket`, `Documents__Minio__UseTls`, `Documents__Minio__AccessKey`, `Documents__Minio__SecretKey`. Для Compose профиль `documents` поднимает закрытый бакет. Локальные реквизиты задаются через `SUR_MINIO_ACCESS_KEY` и `SUR_MINIO_SECRET_KEY`. Бакет внешнего MinIO должен существовать перед использованием.

Метаданные подготовленного файла записываются до вызова хранения. Ключ строится из клиентского хоста, серверного ID и SHA-256. Если ответ MinIO потерян, повтор сверяет размер и содержимое по тому же ключу. Фоновое задание и загрузка защищены клиентской блокировкой PostgreSQL. На время внешнего I/O используется блокировка отдельного задания без открытой транзакции. Пределы результата составляют 20 000 строк источника и 64 МиБ готового файла. Для XLSX дополнительно действует предел длины ячейки Excel.

Сквозные проверки выполняются на двух тестовых клиентах с отдельными базами и одним закрытым бакетом. Для сценария восстановления прервите процесс после PUT в MinIO и до записи статуса в PostgreSQL, затем повторите операцию и проверьте тот же идентификатор и SHA-256. Для проверки отзыва права получите файл, измените матрицу прав и повторите скачивание с новым JWT пользователя.
