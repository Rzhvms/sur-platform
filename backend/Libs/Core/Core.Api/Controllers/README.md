# Базовые контроллеры Core.Api

Базовые контроллеры определяют назначение API, общий маршрут и правила доступа. 

| Базовый класс | Маршрут при `[Route("users")]` и версии v1 | Доступ                                                                          |
|---|---|---------------------------------------------------------------------------------|
| `BasePublicController` | `/api/v1/public/users` | Открытый или с авторизацией - определяется контроллером и его действиями        |
| `BaseProviderController` | `/api/v1/provider/users` | Авторизованный пользователь с административным правом                           |
| `BaseInternalController` | `/api/v1/internal/users` | Без требования авторизации в приложении; внешний доступ закрывается через nginx |

Все три типа контроллеров отображаются в Swagger.

## Подключение

В приложении регистрируются контроллеры и компоненты Core.Api:

```csharp
services.AddControllers();
services.AddCoreControllers();
```

Вместо `AddCoreControllers()` можно вызвать `AddCoreApi()`, который уже включает эту регистрацию. Используется один из этих способов, чтобы не добавлять соглашение маршрутов повторно.

`AddCoreControllers()` подключает:

- Версионирование API по адресу запроса
- Группировку методов по версиям для Swagger
- `ControllerRouteConvention` через `services.Configure<MvcOptions>`
- Политику административного доступа `provider`

Аутентификация пользователя, например JWT Bearer, настраивается в самом микросервисе. В конвейере обработки запросов `UseAuthentication()` и `UseAuthorization()` вызываются после выбора маршрута и перед выполнением контроллеров.

## Формирование маршрутов

`ControllerPrefix.ApiVersionPrefix` задает общий шаблон:

```text
api/v{version:apiVersion}
```

`ControllerPrefixAttribute` задает следующую часть маршрута: `public`, `provider` или `internal`. Атрибут уже установлен на соответствующем базовом контроллере.

`ControllerRouteConvention` объединяет общий шаблон, префикс типа и маршрут конкретного контроллера. Например, `[Route("users")]` на наследнике `BasePublicController` дает `/api/v1/public/users` для версии v1.

В `[Route]` указывается относительный маршрут без повторения `api`, версии и типа контроллера. Абсолютные маршруты с началом `/` или `~/` обходят объединение префиксов и для этих контроллеров не используются.

## Версионирование

Версия читается из сегмента адреса с помощью `UrlSegmentApiVersionReader`. У маршрутов базовых контроллеров этот сегмент обязателен.

Контроллер без явного объявления версии относится к v1. Поддерживаемые версии можно задавать атрибутом `ApiVersion` из пространства имен `Asp.Versioning` на конкретном контроллере:

```csharp
[ApiVersion("2.0")]
[Route("users")]
```

При наследовании от `BasePublicController` такой контроллер обслуживает `/api/v2/public/users`.

Для отдельных реализаций одной операции создаются контроллеры с одинаковым относительным маршрутом и разными атрибутами `ApiVersion`. Если один контроллер поддерживает несколько версий, на нем указываются несколько таких атрибутов. Различающиеся по версиям действия можно связать с нужной версией через `MapToApiVersion`.

На общих базовых контроллерах конкретная версия не закрепляется.

`AssumeDefaultVersionWhenUnspecified = true` позволяет использовать версию по умолчанию для существующих маршрутов без сегмента версии. У маршрутов с шаблоном `v{version:apiVersion}` эта настройка не делает сегмент версии необязательным.

## Public

Public — REST-методы клиентского приложения. Они могут быть как открытыми, так и требующими авторизации.

`BasePublicController` и `PublicControllerAttribute` сами по себе не требуют авторизации. Доступ задается стандартными атрибутами ASP.NET Core:

- `[Authorize]` на действии защищает отдельный метод
- `[Authorize]` на контроллере защищает все его действия
- `[Authorize(Policy = "имя политики")]` требует выполнения указанной политики
- `[AllowAnonymous]` открывает отдельное действие внутри защищенного контроллера или при наличии глобальной политики авторизации

На базовом Public-контроллере `[AllowAnonymous]` не устанавливается: унаследованный атрибут отменил бы проверки авторизации у его наследников.

## Provider

Provider — административные REST-методы.

`BaseProviderController` использует `ProviderControllerAttribute`, который требует выполнения политики `ControllerPolicies.Provider`. Политика регистрируется в `AddCoreControllers()` и проверяет:

- Пользователь авторизован
- В его утверждениях есть тип `ControllerPolicies.RightsClaimType` со значением `ControllerPolicies.AdminRight`

Текущие значения констант — `provider`, `right` и `admin` соответственно. При использовании JWT токен должен содержать утверждение `right=admin`. Проверяется право, а не название роли или признак `IsSystem`.

Значение административного права можно передать явно: `services.AddCoreControllers(adminRight)`. SurPlatform передаёт GUID `IdentityRights.Admin`, совпадающий с правом в JWT и начальных данных БД. Дополнительная регистрация политики `provider` в микросервисе не требуется.

Неавторизованный запрос получает 401, а запрос авторизованного пользователя без нужного права — 403 при использовании JWT Bearer.

На административные контроллеры и их действия `[AllowAnonymous]` не ставится, поскольку он отменяет проверку политики авторизации.

`ControllerRouteConvention` отклоняет Provider-контроллер с `[AllowAnonymous]` и абсолютные маршруты на контроллерах и действиях всех трёх типов при построении модели MVC.

## Internal

Internal — обычные внутренние REST-методы с маршрутом `/api/v{version}/internal/...`.

`BaseInternalController` задает префикс маршрута. `InternalControllerAttribute` обозначает тип контроллера. Требований авторизации или отдельных служебных учетных данных они не добавляют. Методы видимы в Swagger. В SurPlatform проверка сессии требует схему SurInternal, а nginx блокирует внутренний маршрут.

Внешний доступ к Internal закрывается на уровне nginx для всех версий API. Прямой доступ извне к порту приложения также ограничивается средствами инфраструктуры. Сам префикс `internal` сетевой доступ не блокирует.

## Swagger

API Explorer подставляет номер версии в адреса и объединяет методы в группы. Значение `ApiVersionGroupNameFormat = "'v'VVV"` задает имена групп: `v1`, `v2`, `v1.1`. Оно используется для документации и не определяет шаблон маршрута.

`SubstituteApiVersionInUrl = true` заменяет параметр версии в документации на фактическое значение: например, `/api/v1/public/users`.

В SurPlatform `ConfigureSwaggerOptions` создает отдельный документ для каждой обнаруженной версии, а Swagger UI показывает эти документы для выбора. Public, Provider и Internal входят в документацию соответствующей версии.
